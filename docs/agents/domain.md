# Domain docs

Single-context layout: root GLOSSARY.md and docs/adr/.

Before exploring code, read GLOSSARY.md if present and ADRs
relevant to the area being changed.
If absent, proceed silently; create domain docs lazily through
domain-modeling when terms or decisions are resolved.

Use glossary terms in issues, proposals, hypotheses, and tests.
Reconsider unfamiliar terms; note real vocabulary gaps for
domain-modeling.

Explicitly flag proposals that contradict an ADR, citing the
decision and explaining why it should be reopened.
